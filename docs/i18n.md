# The app in Indonesian: how to translate a screen

sprint2go speaks English and Bahasa Indonesia. English is the source: the English text in the code is the key, so a
string nobody has translated yet simply shows English. This page is for everyone translating an app; CLAUDE.md's bar
still applies to every screen you touch.

## 1. The API

All in `src/i18n/`. No React and no browser at import time in `index.ts` and `format.ts`: the server and the unit tests
import files that call `t()`, and get English. A file the server imports (`src/sandbox.ts`, `needsYou.ts`,
`data/pricing.ts`…) imports them by their full path, `from './i18n/index'` and `from './i18n/format'`: Node can't
import a folder (`server/register.mjs` only adds ".ts"), and only `t`, `tn`, `tx`, `mark` and the format helpers work
there (no React: no `tj`, no `useLang`).

```ts
import { t, tn, tx, mark, msg, phrase, textOf } from '../i18n';
import { tj } from '../i18n/tj';                   // a sentence with React elements in it (section 2)

t('Save')                                        // "Simpan"
t('Sign in to {product}', { product: brand.name }) // "Masuk ke sprint2go"
tn(count, '{n} task', '{n} tasks')               // "3 tugas" ({n} is filled for you, written the local way: 1.234)
tx('state', 'Open')                              // the same English meaning something else: key "state::Open"
mark('Account')                                  // returns 'Account' unchanged; translate it where it's shown: t(s.label)
msg('{name} assigned you {task}', { name, task })// { text: English, tr: { key, vars } } for things saved and read later
phrase('“{title}”, due {due}', { title, due })   // a part of a msg() that is translated on its own when read
textOf(notice)                                   // a saved msg() in the reader's language (or its text as saved)
```

- `{name}` placeholders are filled from the values. Write `{Name}` in a translation to get the value with a capital first
  letter: `t('Past {projects}', { projects: term.many })` can read `'{Projects} lama'` in Indonesian.
- `useLang()` (`src/i18n/useLang.ts`) gives the active language and re-renders on a switch. The whole app re-renders on a
  switch anyway (`main.tsx`), so you only need it to put the language in a `useMemo`/`useCallback`'s deps.
- `getLang()`, `locale()` ('en-GB' or 'id-ID'), `setLang(l)`, `LANGS` (each language named in its own language).

### Dates, times, numbers, money: `src/i18n/format.ts`

Never write month or weekday names by hand, and never `toLocale…('en-GB')` or `toLocale…([])` for something people read.

| Helper | English | Indonesian |
|---|---|---|
| `fmtDay(d)` | 8 Oct (8 Oct 2025 in another year) | 8 Okt |
| `fmtDayLong(d)` | 8 October 2026 | 8 Oktober 2026 |
| `fmtWeekday(d)` | Thu 8 Oct | Kam, 8 Okt |
| `fmtWeekdayLong(d)` | Thursday 8 October | Kamis, 8 Oktober |
| `fmtMonth(d)` | October 2026 | Oktober 2026 |
| `fmtTime(d)` | 14:30 | 14.30 |
| `fmtDateTime(d)` | Thu 8 Oct, 14:30 | Kam, 8 Okt, 14.30 |
| `fmtDayWord(d)` | Today / Tomorrow / Yesterday / Thu 8 Oct | Hari ini / Besok / Kemarin / Kam, 8 Okt |
| `fmtAgo(d)` | just now, 5 min ago, 3 hours ago, 2 days ago | baru saja, 5 menit lalu, … |
| `weekdayNames('narrow')` | M T W T F S S (Monday first) | S S R K J S M |
| `weekdayName(0)`, `monthNames('short')` | Sunday, Jan… | Minggu, Jan… |
| `fmtNumber(n)`, `fmtPercent(0.42)` | 1,234.5, 42% | 1.234,5, 42% |
| `fmtMoney(n)` | Rp 39.000 (rupiah reads the same in both) | Rp 39.000 |
| `fmtList(['a','b','c'])` | a, b and c | a, b, dan c |
| `fmtDate(d, opts)` | anything else Intl can do | |

`d` is a Date, a timestamp, an ISO string or a day as `YYYY-MM-DD` (read at local noon).

## 2. The rules

**Call `t()` while rendering, never at import time.** A constant built when the file loads keeps the language it was
built in. For tables of words:

```ts
// Wrong: English forever.
const QUICK = [['Today', today], ['Tomorrow', tomorrow]];
// Right: a function, called while rendering.
const quick = () => [[t('Today'), today], [t('Tomorrow'), tomorrow]];
// Right: a getter (APPS in AppRail.tsx).
{ id: 'home', get name() { return t('Home'); } }
// Right: mark() where it's defined, t() where it's shown (the check script reads the mark()ed words).
const SECTIONS = [{ id: 'account', name: mark('Account') }];  …  <span>{t(s.name)}</span>
```

Also wrong: `useState(() => t('…'))` for text (it keeps the first language), and text built inside `useMemo` without
the language in its deps (`const lang = useLang()`, then `[…, lang]`). Default parameters are fine
(`placeholder = t('Choose…')` runs on every render).

**Translate whole sentences, never glued fragments.** Word order differs: "Past projects" is "Proyek lama", "Sent to
Nadia" is "Terkirim ke Nadia", "3 tasks moved" is "3 tugas dipindahkan".

```tsx
// Wrong: three pieces nobody can put in Indonesian order.
{`${t('Moved to')} ${where}, ${t('still in')} “${stage}”.`}
// Right: one sentence with placeholders.
{t('Moved to {where}, still in “{stage}”.', { where, stage })}
```

When a sentence has a link, a button or a bold name inside it, keep the sentence whole with `tj()`
(`src/i18n/tj.tsx`): its placeholders take React elements, and each language puts them where its word order wants.

```tsx
{tj('Joining a team instead? Ask them to invite {email}, then {signOut} and open their link.', {
  email: <b>{me.email}</b>,
  signOut: <button className="link-btn" onClick={signOut}>{t('sign out')}</button>,
})}
```

**Plurals.** `tn(n, '{n} file', '{n} files')`. Indonesian has one form: its dictionary has one entry, keyed by the English
plural (`'{n} files': '{n} file'`). Never `n === 1 ? '' : 's'` in English text.

**Never translate data.** Names, titles, messages, emails, file names, a company's own stage names: they are what
people typed. Only words the app itself writes go through `t()`.

**The word `t` is taken.** Many callbacks call their parameter `t` (a task, a thread). Inside them `t('…')` calls the
task: TypeScript says "This expression is not callable". Rename the parameter (`task`, `th`, `tm`), not the import.

**Errors from the server.** The server answers in English. Show its fixed messages with `t(error)`: the server area's
dictionary (`src/i18n/id/server.ts`, or your own area for messages only your screens show) holds the Indonesian, keyed
by the server's exact text. Messages with names or numbers inside stay English until the server sends a key.

**Things saved now and read later** (notices, a task's history, anything someone else reads): save
`...msg('{name} assigned you {task}', { name, task })`, which keeps the English `text` and a `tr` with the key and
values, and show `textOf(n)`. Each reader sees their own language. A value can itself be a `phrase()` that is translated
when it's read (App's `describeP(task)` gives `“Brief” for KopiKita, due tomorrow` in the reader's words). Push
notifications and emails use `text` (English) until the server learns each person's language. Notices already do this:
`Notice.tr` in `src/types.ts`, App's `notify(userId, kind, msg(…), link)` and `clientActions.ts`'s `tell`. Still to do,
by their owners: a task's history (`logTask` in App.tsx, tasks), chat's system lines (chat), the server's notices
(server).

**Toasts.** App's toast shows `t(text)` and `t(label)`, so a fixed English toast or button label from code nobody has
translated yet still comes out in Indonesian once its words are in a dictionary. Translate them where they're made
anyway (`showToast({ text: t('Saved'), action: { label: t('Undo'), … } })`): the check only sees written-out keys.
`SwipeRow` does the same with its `label` and `done`; `ActionSheet` labels are shown as given.

**What a company calls its work.** `term.one`, `term.many`, `term.One`, `term.Many` (`src/terms.ts`) give "project",
"projects" or "client", "clients", already in the active language ("proyek", "klien"). Use them as values in sentences:
`t('All {projects}', { projects: term.many })`.

## 3. Area files and who owns them

Each area's Indonesian lives in `src/i18n/id/<area>.ts`, merged in `src/i18n/id/index.ts` (loaded only when someone
picks Indonesian: English users never download it). A big area can split its words into parts, `<area>.<part>.ts`
(settings has `settings.ai.ts`, `settings.company.ts`, `settings.mail.ts`, `settings.imports.ts`): import each part in
`id/index.ts` next to its area. **Only edit your own area files.** A word used everywhere may also be
in `common.ts` (Builder 1's); you can repeat it in your file with the same value. A different value for the same key in
two files is a conflict (the check warns; the last file loaded wins everywhere): use `tx('context', …)` for your sense.

## 5. Tone

The landing page (`src/landing/i18n.ts`) is the house style. Read its Indonesian before you start.

- Address people as **Anda** (capital A), never "kamu".
- Buttons are short imperatives: Simpan, Kirim, Batal, Hapus, Tambah, Buka, Undang.
- Natural sentences, never word for word. "Nothing here yet" is "Belum ada apa-apa di sini", not "Tidak ada di sini
  belum". Shorter is better; drop English filler ("just", "simply") rather than translate it.
- The same plain, specific copy rules as English: no em dashes (in either language, also no en dashes as punctuation),
  no exclamation marks in the app, and the screen still answers "what do I need to do now?".
- Common words the app's people already use stay English: email, chat, link, file, upload in prose is "unggah".
- Capitals: sentence case, like English. Day and month names are capitalised in Indonesian (Senin, Oktober).

## 6. Checking

```sh
node scripts/i18n-check.mjs                    # per area: used, translated, missing; fails on placeholder problems
node scripts/i18n-check.mjs --missing tasks    # what's still English in an area (or a path: src/components/tasks/)
node scripts/i18n-check.mjs --todo tasks       # text on screen that isn't in t() yet (a guess, read it)
node scripts/i18n-check.mjs --unused           # entries no code uses
node scripts/i18n-check.mjs --strict           # also fails on missing words, conflicts and copy problems (later)
```

It fails on placeholders that differ between the English and the Indonesian, on `t('… {x} …')` called without a
value for `{x}`, and on a file the server or the scripts load that imports `src/i18n` as a folder (or `tj`/`useLang`,
which need React): those would crash the server. It warns on conflicts, dashes and a capitalised "Sprint2go"; finish
with no warnings that name your files. CI runs it (`.github/workflows/ci.yml`).

Then look at every screen you translated at **320, 375 and 1440 px, in both languages and both themes**. Indonesian is
about a third longer than English: watch buttons that clip, labels that wrap into two lines in a row, segmented controls
and tab bars that overflow, and headings that orphan a word. Fixes, in order of preference: let the row wrap
(`flex-wrap`, `min-width: 0`), shorten the Indonesian, then `text-overflow: ellipsis` with the full text in `title`.
To switch: Settings, Account, Language; or before signing in, the switch under the sign-in card; or in a headless
browser, a context with `locale: 'id-ID'`.

## 7. How the language is chosen

- **Signed in**: the person's own pick (`Settings.language`, Settings, Account; it syncs between their devices like
  their other settings), else their company's default (`Workspace.language`, Settings, General), else the device's.
- **The device's**: what was last picked on this device (the landing page's switch, the sign-in page's switch, or a
  signed-in pick, all kept in `localStorage['s2g-lang']`), else the browser's language.
- **Before signing in** (sign in, sign up, reset, invite, two-step): the device's. The switch under the card picks.
- `main.tsx` loads the words before the first render, so nobody sees English flash before their language. A switch
  loads the words first, then re-renders everything at once.

## 8. Handed over: what the foundation found in other areas

Builder 1's areas are fully translated (the check shows 0 missing for shell, ui, settings, auth, home, onboarding).
These are in other areas and were left for their owners; each is wrapped where Builder 1's screens show it, so adding the
words in your own file (and `mark()` or a getter where it's defined) is usually all it takes.

- **Tasks (Builder 4)**: `src/stages.ts` (the built-in stage names, `KIND_INFO`, `TONE_NAME`, "Waiting for review"),
  `dueLabel()` and `taskDates.ts` (due words and dates, still English and `toLocaleDateString([])`), "(me)" in the
  assign picker, Quick Add's date words (it parses English: Indonesian words are a feature to decide), and a task's
  history: `logTask` in App.tsx and TaskStages write English lines; give `TaskEvent` a `tr` and use `msg()`. Words
  already chosen elsewhere: "Dikerjakan" (In progress), "Menunggu Anda" (Waiting on you), "Menunggu {who}".
- **Meet (Builder 3)**: `JOIN_MODES` in `src/meetingLinks.ts` (Settings shows `t(label)`), the meeting language names in
  `src/data/languages.ts` (shown with `t()`), and the notetaker is "notulis" in Home and Settings.
- **Drive (Builder 3)**: `fmtSize` in `src/data/drive.ts` writes "1.5 GB"; Indonesian wants "1,5 GB" (`fmtNumber`).
- **Chat (Builder 3)**: system lines saved into channels ("created #…", "📌 New task for you: …") are English text.
- **Calendar (Builder 2)**: the holiday country names in `src/data/holidays.ts` (Settings shows `t(name)`), and Settings
  says "The calendar couldn’t be read. It will be tried again later." for the holiday calendar: keep that wording.
- **Projects (Builder 4)**: `PROJECT_TYPES` in `src/terms.ts` are values; show them with `t(type)`. Settings already
  has Internal, Partner, Vendor, Acara (Event), Lainnya (Other).
- **Mail (Builder 2)**: Mail's folder names (`FOLDER_TITLES`) and toasts in App.tsx; the title switcher options for
  Mail, Meet, Projects and Drive in App.tsx (`mobileSwitcher`, `useTitleMenu('mail')`).
- **Guest (Builder 5)**: a guest's language is their own pick (English or Bahasa Indonesia in the portal's account
  menu, or on Shared with you; it follows them to their other devices), else their device's, never the inviting
  company's default (`ClientRoot` in Root.tsx).
- **Server (Builder 6)**: notices the server writes (`server/*.ts`: reminders, read tracking, imports, tables, WhatsApp)
  are English text: add `tr: { key, vars }` like `msg()` makes. Messages with names or numbers inside (import errors,
  mail readiness, billing's read-only reasons, the AI key notes) stay English until the server sends a key; the fixed
  ones are already in `settings*.ts` and `auth.ts` (keep the same Indonesian, or the check warns). Push notifications
  and emails are English until the server knows each person's `Settings.language`.
- **Misc (Builder 6)**: the demo data (`src/data/team.ts`, `workspaces.ts`, `mock.ts`, the try-out) is content, so it
  stays English unless we decide the demo company should speak Indonesian.
